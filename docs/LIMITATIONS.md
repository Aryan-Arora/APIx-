# Known limitations and acceptance boundaries

1. **All fare data is synthetic.** Every quote is generated by a calibrated simulator (`is_synthetic=true` on every row), not scraped from real airline/OTA sites. Live scraping adapters exist as documented stubs (`docs/SCRAPING.md`); none has successfully collected real data. This is labelled throughout the UI and API — never presented as observed data.
2. **DGCA route-level average-fare data is still placeholder.** Real DGCA fare figures could not be sourced as a clean downloadable dataset (see `docs/BACKTEST.md` for what was actually found — sparse, non-systematic Parliament-reply figures, not a usable time series). `MAPE_vs_dgca_fares` and `backtest_results` rows are withheld from the UI rather than computed against placeholder data.
3. **The MoSPI CPI trend backtest uses real data but a tiny sample.** `data/reference/cpi_transport_group_index.csv` holds 3 real months (Dec 2024, Nov 2025, Dec 2025) of MoSPI's CPI sub-group `6.1.03 "Transport and communication"` (Base 2012=100). Only 2 of those months overlap with any APIx history, so the computed correlation/direction-agreement (both currently 1.0) are not statistically meaningful at n=2 — the API attaches this caveat directly to the metric notes. See `docs/BACKTEST.md` for the base-year discontinuity that prevents extending this series past Dec 2025 with the same methodology.
4. Basket and lead weights (`data/reference/routes.csv`, `lead_weights.json`) are documented ASSUMPTIONS, not sourced DGCA passenger-share/booking-distribution data.
5. One minute of requests is limited per direct client IP per API process. Proxy trust and distributed rate limiting are production follow-ups. The public demo key (`demo-readonly-key`) is not a confidentiality boundary — it's intentionally public and read-only.
6. Next.js public variables (`NEXT_PUBLIC_API_BASE`, `NEXT_PUBLIC_API_KEY`) are build-time values baked in at deploy; changing them requires a redeploy, not just an env-var edit.
7. Local API tests pass on Python 3.11.15 and 3.13; CI and the Docker image target 3.11.
8. Reference summaries (`/backtest`) are pipeline-wide and do not support synthetic-mode filtering.
9. Database filters assume UTC observation timestamps. Database role permissions, RLS on the Fly Postgres instance, TLS verification, live table size and pool capacity have not had a dedicated production security review beyond the basic setup done for this deployment.

Future work: real live scraping (see `HANDOFF_NOTES.md`'s live-scraping handoff section for IndiGo findings so far); real DGCA route-level fare data if a better source surfaces; verified traffic weights; a longer real-CPI reference series once MoSPI publishes more months under the current base year (or a rebasing methodology is agreed); cell-level imputation/coverage reports; distributed rate limits; persistent filter URLs; bounded/cached aggregate endpoints; production performance measurement.
